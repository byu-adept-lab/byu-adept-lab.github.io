{%- comment -%} Google Analytics 4 (gtag.js). The measurement ID comes from `google_analytics` in _config.yml. It is deliberately the SAME value as on twkillian.github.io: one GA4 property, one web data stream, both sites carrying an identical tag. Not two streams. Why one stream rather than two: the PI's personal site links here from its nav, so visitors cross between the two hostnames mid-session. GA4 only stitches a session across domains when both domains carry the same tag. Two streams would still land on one dashboard, but every crossing would end the session, invent a new user, and log the other site as self-referral traffic. The two sites stay separable in reports via the `hostname` dimension. Both sites are *.github.io, and github.io is on the Public Suffix List, so no cookie can be set at the shared parent and each hostname keeps its own cookie jar. Cross-domain stitching therefore has to be switched on explicitly in the GA4 admin (Admin > Data streams > the web stream > Configure tag settings > Configure your domains). It will not happen implicitly just because both hosts happen to end in github.io. Two guards, both necessary: - jekyll.environment must be "production", so local `jekyll serve` previews and scratch builds never report into real data. GitHub Pages satisfies this on its own: actions/jekyll-build-pages exports JEKYLL_ENV=production, and that action is what builds this site. - the ID's stripped length must be non-zero. There is no String#blank? in this Liquid stack, so an "x != blank" comparison silently evaluates true for an empty string and would emit a broken gtag('config', ''). Piping through strip and size is the test that actually holds. With the ID unset this include renders nothing whatsoever.
